GetSales runs a managed MCP server for your workspace at `https://mcp2.getsales.io/mcp/public`. Claude, Cursor, ChatGPT or a custom agent runtime can build tables, enrich rows, author and run workflows, read the inbox and the AI SDR's drafts, train the AI SDR, and watch signals in a workspace you own.

MCP and REST are the same contract. Every tool maps 1:1 to an endpoint in the [API reference](/api-reference/overview): one Zod schema defines the tool, the endpoint and this documentation, so an agent and your backend code see identical shapes and work under the same server-side rules.

## One address, or one group at a time

- **The public address, `https://mcp2.getsales.io/mcp/public`.** Four meta-tools over the tools of your workspace. `search_tools` finds tools by what they do (plain words, optionally narrowed to one group with `toolset`, and with `detail: "full"` whole definitions), `describe_tool` gives one full definition, `call_tool` runs a tool by name, and `list_toolsets` is the map. The agent discovers what it needs instead of loading hundreds of definitions into its context.
- **One group alone, `https://mcp2.getsales.io/mcp/<group>`.** Every tool of one group with its full schema, listed directly, for a client that wants them in its tool list without a discovery step: `https://mcp2.getsales.io/mcp/playtables/tables`, `https://mcp2.getsales.io/mcp/inbox`, `https://mcp2.getsales.io/mcp/ai-sdr/training`. The URL is the group id with its dots as slashes.

## The groups

The tools are grouped by the entity they belong to, never by a menu. A prefix exists only where there is a family: `playtables.*` for what belongs to the tables, `ai-sdr.*` for what belongs to the agent, `workspace.*` for what belongs to the workspace (the Settings and Admin panels of the app). The id is what `search_tools` takes as `toolset`.

| Group | What it is for |
|---|---|
| `playtables.tables` | Find or create a table and its views, read how it and the whole workspace are doing, put it away in archive. |
| `playtables.columns` | Build a column, try a prompt on one row, estimate the price, start and stop a run, inspect a cell. |
| `playtables.rows` | The rows of all tables, people and companies: find, read, edit, merge duplicates, read a LinkedIn profile, the feed of what happened to each. |
| `playtables.crm` | The CRM mechanics of rows: pipeline stages, tags, notes, and the stoplist (block, unblock, check a value across every table). External CRMs are `workspace.integrations`. |
| `playtables.sources` | Where rows come from: data sources of six kinds, their items and their funnel. |
| `playtables.workflows` | Build, validate, publish, run and edit a workflow, and decide who enters it. |
| `playtables.workflow-records` | One row per person in a workflow and its tasks: where the person stands, pause, resume, restart, exit, approve or retry a step. |
| `inbox` | Work the inbox: find a thread, read it, reply, approve or cancel drafts, close, hand over, stoplist, tasks, link a thread to a person. |
| `sender-profiles` | Who sends: the sender profile, its variables, its limits, what it did today and by day. |
| `sender-accounts` | Connect and disconnect a LinkedIn account and mailboxes without a browser, send out connect links, pause a mailbox, mailbox settings. Not on the public address. |
| `ai-sdr.agents` | The AI SDR itself: create it, its Brief, Rules, hosts, voice, scenarios, plans, runs and how it did. |
| `ai-sdr.training` | What the AI SDR knows and how it learns: Knowledge (answers and the documents they come from), the golden set, hints, tests on a real thread, one "teach it" entry. |
| `signals` | Who was on your site and who viewed a profile, and the plays that react to a table's facts. |
| `workspace.team` | The General, Profile and Teammates panels: who you are and in which workspace, the onboarding cards and the website read for them, members and invites, account emails. |
| `workspace.access` | The API keys and OAuth panels: which keys stand and what is connected, revoke a leaked key, disconnect an app. Keys are minted over REST, never through a model. |
| `workspace.billing` | The Subscription, Usage and Invoices panels: what was bought, the credits left and what they went on, a price or capacity change, reseller allocations. |
| `workspace.website-tracking` | The Website panel: register a site, hand out the loader, check the installation, key pages and tracked events, reissue the key, the team switches for signals. |
| `workspace.integrations` | The Integrations panel: your own API and your CRMs, connections by key and OAuth, CRM fields, custom tools for columns, catalog prices, the call log. |
| `workspace.webhooks` | The Webhooks panel: subscribe an endpoint to events, test it, read deliveries and bring back what was missed. |
| `workspace.whitelabel` | Reseller Admin: brand, domain, certificate, email domain, clients. |

The public address serves every group but the tools that act on a channel or set up an account for one: a message is sent, approved or sent again in the GetSales app, a sender profile's accounts are connected there too, and a LinkedIn profile is read in the app. The full facade at `https://mcp2.getsales.io/mcp` and the groups' own URLs serve those tools to a signed-in client.

## What to ask

Once a client is connected, the agent picks the tools itself from a plain request. A few that work on day one:

| Ask | What the agent does |
|---|---|
| "Build a table of marketing agencies in Berlin and find their heads of growth" | creates a table, adds a company search as its data source and a Find people column that runs on every row that lands |
| "Which of my tables are still importing?" | searches the data sources by status and reports each table's progress |
| "Find and verify a work email for everyone in this table without one" | adds the enrichment column over the rows that need it and reports the fill's estimate before it runs |
| "Show me the replies from this week that nobody answered" | searches the conversations by state and last inbound message, newest first |
| "Draft an answer to this thread, I will send it myself" | reads the thread and writes the draft in the chat, for you to send from the app |
| "Pause the outbound workflow for the DACH list until Monday" | pauses the workflow and tells you what is parked |
| "What would the AI SDR answer to: do you integrate with HubSpot?" | searches its Knowledge semantically and shows the answer it would give, with the gap if there is none |
| "How many credits do we have left, and what did last week's enrichment spend?" | reads the credit balance and the spend over the week by column |
| "Who from the companies in this table visited the pricing page?" | searches the website sessions by company and page |

Anything that changes state goes through the guardrails below. Reads run straight away.

## Guardrails that matter for agents

- **Dangerous tools preview first.** Each tool that deletes or cancels something, a conversation merge, a site key or an ingest key rotated, a subscription change, a webhook created or changed, and publishing or resuming a workflow: the first call answers a preview and a `commit_token` and changes nothing, and the same call with the same arguments plus the token executes. The token is single use and expires in 300 seconds. A plain write (an edit, a pause, a paid table run, capped by its `max_budget` when it has one) runs on the first call, on the user's word.
- **Server-side rates.** 600 calls and 120 writes a minute per workspace, a batch of at most 16 messages, 25 seconds per backend call, and answers cut to a 48,000-character budget with a note when they were. A search page that does not fit comes back shorter, with `has_more` and `next_cursor` true to the rows it holds, so a plain cursor loop collects every row. Such a page counts as two calls.
- **Typed errors.** A refused tool call is a tool result with `isError: true` and the same 16-code envelope as REST, with `recoverable` and a `suggestion` written for an LLM to act on. See [Envelopes and errors](/concepts/envelopes-and-errors).
- **Every answer carries the trace.** `_meta.trace_id` on every tool result and the `X-Trace-Id` response header. Quote it when reporting a problem.

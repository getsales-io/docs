A sender profile sends email from its mailboxes, and an email step sends from the ones that are active, in turn. A Google Workspace or Microsoft 365 mailbox connects in the app by signing in with Google or Microsoft. Any other mailbox connects from its own IMAP and SMTP settings, in the app or through the API. Every mailbox lands on a dedicated email server of your workspace, which comes with an email package of a paid plan.

<Tip>
**Give this to Creator**, the assistant inside the app, after the mailbox is connected. An assistant connected at the public address ([Connect your AI assistant](/kb/ai/connect-your-ai-assistant)) cannot change a mailbox's settings: it leaves them to the app.

"In GetSales, find the sender profile of Maya Chen and read its mailboxes. For the mailbox maya@acme.example, set the daily send limit to 30, the interval between emails to 180 seconds, warmup on, the From name to Maya Chen, and make it the primary mailbox. Then read the mailbox back and show me its settings."
</Tip>

## Where does a new mailbox land?

Every mailbox a GetSales workspace connects lands on a dedicated email server for that workspace. One email package of the plan is one server of the package's size: 100, 500, 2,000 or 10,000 inboxes. GetSales sets the server up after the purchase, usually within minutes, and the workspace's owner gets an email when it is ready. A mailbox connects only to a server that is ready and has an inbox free.

- **The trial** carries no email, so it has no server: **Add mailbox** reads **No email in your plan yet**.
- **The Free plan** holds no inboxes, so no mailbox connects on it. A workspace that never had email reads **No email in your plan yet**, and a server left from an ended plan reads as paused.
- **A paid plan** holds one email package, so one server. A package is bought with **Buy email** in **Add mailbox** or in **Settings**, **Subscription**: [Plans, credits and billing](/kb/workspace/plans-credits-and-billing).
- **Over the API**, `POST https://api2.getsales.io/unibox/v1/api/sender-profiles/{sid}/mailboxes/servers` ([`list_sender_profile_mailbox_servers`](/api-reference/unibox/sender_profiles/list-the-email-servers-for-a-new-mailbox), REST only, with the sender profile's sid in the path) lists the servers a new mailbox of that sender profile can land on, oldest first: each with its `sid` (`em_bx_...`), `name`, `plan` (`starter` for 100 inboxes, `growth` 500, `agency` 2,000, `dedicated` 10,000), `status` (`provisioning`, `resizing`, `active`, `suspended`, `failed`), `suspended_reason` (`payment_failed`, `unpaid`), `destroy_at` (the moment a server paused for billing is deleted with its mailboxes unless it is paid for again: [the unpaid server's week](/kb/workspace/plans-credits-and-billing#what-happens-to-an-email-server-nobody-pays-for), null otherwise), `inbox_capacity`, `inboxes_used`, and `setup` (`step` of `steps`) while it is being set up or changing its plan. A mailbox lands only on an `active` server with an inbox free, and an empty `servers` list is a workspace with no email server. Beside the list, `default_server_sid` is the server a connect that names none lands on, and `inboxes_paid` is the number of inboxes the plan pays for: above zero with an empty list, the paid server is on its way.

## What do you need before connecting a mailbox?

Connecting a mailbox to a sender profile needs:

- **A sender profile.** Create one on [https://app.getsales.io/sender-profiles](https://app.getsales.io/sender-profiles) with **New profile**: [Sender profiles](/kb/sender-profiles/sender-profiles).
- **An email server with an inbox free.** It comes with an email package of a paid plan: [Where does a new mailbox land?](#where-does-a-new-mailbox-land).
- **A free inbox in the plan.** The plan's email inboxes are shared by all the workspace's sender profiles, and each connected mailbox takes one. When every inbox is in use, a new mailbox is refused with `402` `email_inboxes_full`: **Every inbox your plan holds is in use. Add inboxes, or detach a mailbox you no longer need.** in **Add mailbox**, and "All 100 inboxes of this workspace's plan are in use. Detach a mailbox you no longer need, or add inboxes in Settings, Billing." over the API (your plan's number in place of 100). Over the API, a plan with no inboxes answers "This workspace's plan has no inboxes. Pick a plan in Settings, Billing." Add inboxes in **Settings**, **Subscription**: [Plans, credits and billing](/kb/workspace/plans-credits-and-billing).
- **For Google Workspace, the admin's one-time trust**, below.

## What must a Google Workspace admin do before a mailbox connects?

A Google Workspace admin trusts the GetSales app once for the whole domain. Until it is done, Google blocks the sign-in.

1. Open the [Google Workspace Admin console](https://admin.google.com/ac/owl/list?tab=configuredApps) at the list of configured apps.
2. Click **Configure new app**.
3. Search for the app by its Client ID, which the **Google** tab of the **Add mailbox** dialog shows with a **Copy** button once the workspace has an email server:
   `73809045414-4br5ovdbf9aqece81vgnmtpedcjg2jlc.apps.googleusercontent.com`
4. Select it, give all users **Trusted** access and click **Finish**. Any other access level blocks the connection.

## What does a Microsoft 365 mailbox need before it connects?

A Microsoft 365 mailbox connects through Microsoft's own consent page, so it needs the mailbox's user to be allowed to approve outside apps. When the organisation lets only admins approve them, Microsoft asks for an admin's approval: a Microsoft 365 admin approves the app, and the user signs in again.

The **Microsoft** tab of the **Add mailbox** dialog (shown once the workspace has an email server) also lists steps for a Microsoft 365 admin: in the [Microsoft 365 admin center](https://admin.microsoft.com/#/homepage), under [Active users](https://admin.microsoft.com/#/users), select the user, open the **Mail** tab, then **Manage email apps**, check both **Authenticated SMTP** and **IMAP**, save, and wait one hour before connecting. GetSales reads and sends a Microsoft 365 mailbox through Microsoft's own mail API on the consent, never over SMTP or IMAP, so these steps are not needed to connect it.

## How do you connect a Google or Microsoft mailbox?

A Google Workspace or Microsoft 365 mailbox connects from the sender profile's **Email** tab: click **Add mailbox**, check the **Email server** it lands on, pick **Google** or **Microsoft**, click **Sign in with Google** or **Sign in with Microsoft**, and allow access in the provider's tab within 15 minutes. It connects in the app only. No MCP tool starts a Google or Microsoft sign-in, Creator's included, and the API reference has no call that does: over the API, only an IMAP and SMTP mailbox connects ([`connect_sender_profile_imap_mailbox`](/api-reference/unibox/sender_profiles/connect-an-imap-mailbox-to-a-sender-profile)).

## How do you buy email from Add mailbox?

**Buy email** opens the purchase window the plan already uses, with one email package of 100 inboxes in it, the smallest. Change the size in the window. A workspace holds one email package.

- **On the trial, the Free plan or with no plan:** **Buy resources** opens with the package and as many LinkedIn sender profiles as the workspace has LinkedIn accounts connected, beside the data subscription every new plan holds, since the purchase replaces the trial with what it holds. A trial with a card on it buys nothing else: **Settings**, **Subscription** opens, which says when the card's plan starts.
- **On a paid plan with no email package:** **Change plan** opens with one package of 100 inboxes added to the plan.
- **On a paid plan that already holds its package:** **Change plan** opens only where a larger size can be taken in the package's place. Where none can, no window opens and the dialog says to write to support, who move your mailboxes to a larger package.
- **Without the Billing Manage permission, on a share of a subscription its buyer manages, on a plan with a change already scheduled, or on a plan that is not active** (a failed payment, a pause): the dialog closes and **Settings**, **Subscription** opens, which says who can buy.

Once the payment or the change goes through, the dialog reads **Payment received. Your email server is being ordered; this window updates by itself.**, and it shows the new server, step by step, as soon as it is listed, reading **setting up** until it is ready. Once it is ready, the dialog picks it by itself, unless you picked a server yourself. A declined card or a refused change leaves the dialog as it was.

## What does a mailbox's Import line import?

The **Import** line of a mailbox connect sets which of the mailbox's conversations come into Unibox and onto people's activity, from its past and from now on:

- **How far back:** **All history** (the default), **Last year**, **Last month**, **New messages only** or **Custom date**. A mailbox's first sync reads its last 90 days, so no choice reaches further back than that, **All history** included. An IMAP mailbox connected through the API can ask for up to 3,650 days with `backfill_days`.
- **Whose:** **People in playtables only** (the default) or **All conversations** (in the menu, **Only with people in my playtables** and **All conversations**). With the first, conversations with people already in your tables come in, a new conversation with anyone else stays out of Unibox (a thread already in Unibox keeps syncing), and someone you add to a table later brings theirs in.

Both change later from the **Import** row of the mailbox's card, in a sheet of its own with **Save**.

## How do you connect an IMAP and SMTP mailbox?

A mailbox on any other host connects from its own IMAP and SMTP settings: on the **IMAP and SMTP** tab of **Add mailbox**, or through the API.

**In the app.** Open **Add mailbox** on the sender profile's **Email** tab, check the **Email server** and pick the **IMAP and SMTP** tab ("For a mailbox of any other provider. It signs in with the mailbox's own IMAP and SMTP settings, right here."). Enter the **Email address** and the password. The **IMAP server** and the **SMTP server**, their ports and their encryption (**SSL/TLS** or **STARTTLS**) fill in from the address: a known provider's own hosts, else `imap.` and `smtp.` on the address's domain. Change them when your provider's differ. The mailbox signs in with the address and one password, and **Use other sign-in names** opens an **IMAP username**, an **SMTP username** and an **SMTP password** for a provider that wants them. Click **Connect mailbox**: GetSales signs in to both servers (**Signing in**) before it creates anything, and the mailbox appears on the **Email** tab. A refusal is said under the field to change, such as "The IMAP server refused this sign-in. Check the address and the password; many providers want an app password." Gmail, Yahoo and iCloud take an app password, not the account's own, and an Outlook.com, Hotmail or Live address is sent to the **Microsoft** tab, since those mailboxes no longer take a password over IMAP.

A mailbox that is connected already is refused with where it is: "This sender profile already has this mailbox. If it stopped working, press Reconnect on its card.", "This mailbox is already on Daniel Okafor." (the sender profile that holds it, or "another sender profile of this workspace" when its name cannot be shown) or "This mailbox is already connected in another workspace. Disconnect it there first." For a mailbox on another sender profile, the dialog's button turns into **Move it here**: confirm **Move this mailbox here?** and it comes over with all its conversations, still connected. **Use another address** clears the field instead. A mailbox the workspace already held on no sender profile is attached as it is: "Mailbox attached with the settings it already had. What you typed here was not applied."

**Through the API.** [`connect_sender_profile_imap_mailbox`](/api-reference/unibox/sender_profiles/connect-an-imap-mailbox-to-a-sender-profile) takes the mailbox's IMAP and SMTP settings and both passwords, signs in to the mailbox's IMAP and SMTP servers before anything is created, and attaches the mailbox to the sender profile, one call per mailbox. The mailbox lands on the email server whose `sid` the call passes as `email_server_sid` (one the servers read lists), or, without it, on the oldest active server with an inbox free. When no server can take it, the call is refused before anything is created: [the refusals](#which-refusals-does-a-mailbox-connect-answer-over-the-api). A script over a CSV file connects a whole list: [Connect mailboxes from a script](/guides/connect-mailboxes) has the call and the IMAP and SMTP refusals, and the plan and email server refusals are [below](#which-refusals-does-a-mailbox-connect-answer-over-the-api).

Google Workspace takes an app password over IMAP, and most other hosts the mailbox's own password. Microsoft 365 takes no password over IMAP, so a Microsoft 365 mailbox connects on the **Microsoft** tab. An AI assistant cannot connect an IMAP mailbox: the passwords never pass through the model, so the call is REST only.

## What settings does a mailbox have?

A mailbox's settings are on its card of the **Email** tab: click the mailbox to open them. Each saves on its own: a typed field when you leave it, the **Warmup**, **Track opens** and **Track clicks** switches when you click them, the tracking domain when you pick it, and **Import** from its own sheet with **Save**.

| Setting | In the API | What it does | Range |
|---|---|---|---|
| **Daily send limit** | `sending_limits.daily_limit` | Emails a day from this mailbox. The head shows how many went today | 1 to 2,000 emails |
| **Interval between emails** | `sending_limits.min_interval_seconds` | The shortest gap between two emails from this mailbox, **Randomised by 20 percent** either way: at 180 seconds, the next email goes no sooner than 144 to 216 seconds after the last | 10 to 3,600 seconds |
| **Warmup** | `warmup_config` | On: **Ramps to the daily limit**, starting low and sending more each day. Off (the default for a new mailbox): **Sends at the daily limit right away** | On or off |
| **From name** | `display_name` | **What the recipient sees in the inbox** | |
| **BCC** | `bcc` | **A copy of every sent email goes there**. In a Unibox reply it shows as a chip you can remove for that one email | Up to 5 addresses, separated by commas |
| **Custom tracking domain** | `email_tracking_domain_sid` | **Links and open tracking run through it**. Only a verified domain can be picked, and **Manage tracking domains** adds one: [Set up a tracking domain](/kb/sender-profiles/tracking-domains) | |
| **Track opens** | `track_opens` | **Counts who opened, unless a step says otherwise**. Greyed until a verified tracking domain is set, with the reason on hover: "Set a verified tracking domain first: opens and clicks are counted through it." | On or off |
| **Track clicks** | `track_clicks` | **Counts link clicks, unless a step says otherwise**. Greyed the same way | On or off |
| **Import** | `history_since`, `history_scope` | How far back, and whose conversations, Unibox imports | |
| Sending hours (API only) | `sending_limits.sending_window` | When this mailbox may send, apart from any workflow's sending window: `time_zone`, `days` (`1` for Monday to `7` for Sunday), `start` and `end` (`HH:MM`). The card has no field for it | Any days and hours, or `null` to send at any hour |

The card's head wears **Primary** on the sender profile's primary mailbox and **Warmup** while the ramp is on, names the provider and the interval in minutes (**Google Workspace · 3 min gap**), counts today's emails against the daily limit (**0 of 30 sent**) and shows the status. Through the API, [`update_sender_profile_mailbox`](/api-reference/unibox/sender_profiles/update-a-sender-profile-mailbox) changes the same settings. How the limit, the interval and the warmup pace a mailbox: [Smart limits and warmup](/kb/sender-profiles/smart-limits-and-warmup#how-do-a-mailbox%E2%80%99s-daily-limit-interval-and-warmup-work).

A signature is not a mailbox setting. It belongs to the sender profile: open its **Variables** tab and fill **Signature** (`variables.signature` on [`update_sender_profile`](/api-reference/unibox/sender_profiles/update-sender-profile), HTML, up to 8,192 characters). It goes into an email only where you place it: **Insert signature** in a reply in Unibox, or the **Signature** chip in a **Send email** step's body. The mailbox appends nothing, and `signature_html` is no longer taken by `update_sender_profile_mailbox`: [Sender profiles](/kb/sender-profiles/sender-profiles#where-does-a-sender-profile%E2%80%99s-signature-go).

## How do you pause, make primary or detach a mailbox?

A mailbox's verbs sit under its settings on the **Email** tab:

- **Make primary** makes it the sender profile's primary mailbox (`is_primary`). The first mailbox connected is the primary until then.
- **Pause sending** stops its sending while it keeps syncing and receiving replies, and **Resume sending** brings it back ([`pause_sender_profile_mailbox_sending`](/api-reference/unibox/sender_profiles/pause-sending-from-a-sender-profile-mailbox), [`resume_sender_profile_mailbox_sending`](/api-reference/unibox/sender_profiles/resume-sending-from-a-sender-profile-mailbox)). A pause GetSales made on its own asks **Why is it safe to send again?** before it resumes. Email steps due on a paused mailbox wait and go out after **Resume sending**, and the sender profile's LinkedIn steps keep going.
- **Move to another sender profile** opens **Move mailbox**: pick a sender profile under **Move to** and click **Move**. The mailbox stays connected and its conversations move with it ([`move_sender_profile_mailbox`](/api-reference/unibox/sender_profiles/move-a-mailbox-to-another-sender-profile) with `to_sender_profile_sid`).
- **Detach** takes it off the sender profile and removes it from GetSales: one inbox of the plan is free again, and to use the mailbox again you connect it again ([`detach_sender_profile_mailbox`](/api-reference/unibox/sender_profiles/detach-a-mailbox-from-a-sender-profile)). A mailbox of your own linked gtm-api workspace stays connected there. To keep a mailbox, move it. A mailbox that is the sender profile's last channel cannot be detached: move it, or delete the sender profile.

Beside them, a line such as **Synced 7 hours ago** says when the mailbox last synced.

## How do you check a mailbox's sending domain?

A mailbox's card has a **Domain health** row ("How mail servers read acme.example"): one mark for each of the domain's MX, SPF, DKIM and DMARC records, with a sentence under the one that needs work, such as "acme.example has no SPF record, so mail servers cannot tell that your provider may send for it, and more of your mail lands in spam. Add the TXT record your mail provider gives you." MX is what lets replies reach the mailbox, and SPF, DKIM and DMARC are what keeps its mail out of spam. A DKIM key under a selector of your provider's own cannot be read from outside: the row says so, and it counts as no problem.

A mailbox whose domain is missing a record, or holds one that reads wrong, wears an amber mark on its mail chip in the sender profiles list and on its card, such as **DNS needs fixing: SPF, DMARC**. The mark is a warning: it never holds a send, and such a mailbox is not counted under **Needs attention**.

Fix the record at the domain's DNS host, then click **Check again** on the row: the domain is looked up at once, at most once a minute for one domain. Left alone, the records are read again every six hours. Through the API, [`list_sender_profile_mailbox_domain_health`](/api-reference/unibox/sender_profiles/list-the-sender-profile-mailboxes-domain-health) answers every mailbox of the workspace with its `status` (`problem`, `ok` or `unknown`), its four `records` and `checked_at`, and with `email_account_sid` and `refresh: true` it looks one mailbox's domain up now.

## How should a new mailbox start sending?

A new mailbox, or a mailbox on a new domain, should start slow: turn **Warmup** on for a mailbox that has not sent cold email before, and raise its daily send limit over weeks rather than days. Mail providers judge a mailbox by its bounces and spam complaints, and when a provider blocks a mailbox's emails, GetSales pauses its sending: [Why a mailbox stopped sending](/kb/sender-profiles/troubleshooting#why-did-a-mailbox-stop-sending).

## How does a sender profile send from several mailboxes?

A sender profile with several mailboxes sends each new email from its active mailbox least recently used, each within its own daily limit and interval, so several mailboxes send more in a day than one. A mailbox that is paused, still syncing or needs reconnecting is skipped for new emails until it is back. When every mailbox that could send is paused, a due email waits and goes out after the resume. When the only one left is in its first sync, the email waits up to 24 hours from the start of that sync, then fails with `mailbox_first_sync_unfinished`. An email step fails with `sender_profile_has_no_mailbox` ("The sender has no mailbox connected.") only when no mailbox of the sender profile can send again by itself. A follow-up in a thread goes from the mailbox that started the thread: it waits while that mailbox is paused, syncing, at its daily limit or outside its own sending hours (`sending_limits.sending_window`, set over the API), and fails with `sender_profile_has_no_mailbox` while that mailbox needs reconnecting. A sender profile can hold as many mailboxes as the plan has inboxes free.

## How do you check that a mailbox is connected?

- The mailbox card reads **Syncing** while its first sync runs ("Reading this mailbox's mail for the first time. Sending from it starts when that is done."), then **Active**, and its head counts today's emails against the daily limit, such as **0 of 30 sent** before the first one goes.
- The sender profile's **Activity** tab lists the mailbox as attached, such as **Mailbox maya@acme.example attached over Google Workspace**, then **History synced** with the threads and messages the import brought in.
- Through the API, [`search_sender_profiles`](/api-reference/unibox/sender_profiles/search-sender-profiles) lists the mailbox in `mailboxes` with `status` `connecting`, then `active`.

## Why does a mailbox not connect?

A mailbox does not connect when the workspace has no email server or its server cannot take one (setting up, full, paused, failed or gone), when every inbox of the plan is in use, when a Google Workspace admin has not trusted the app or a Microsoft 365 organisation wants an admin's approval, or when the consent tab was closed before it finished or the consent took longer than 15 minutes.

When the server cannot take the mailbox, a click on **Sign in with Google** or **Sign in with Microsoft** opens nothing and a line under **Email server** says why. A refusal from GetSales after the click puts its line there too, and the dialog reads the servers again.

| What happens | What to do |
|---|---|
| **No email in your plan yet**, or **This workspace has no email server yet. Buy email to get one.** | The workspace has no email server, as on the trial or a plan with no email package: click **Buy email** |
| **Your plan includes email, and its server is being ordered.** | The plan pays for an email package and its server is not listed yet. Do not buy again: the dialog updates by itself, and write to support@getsales.io if it still reads so 15 minutes after the payment |
| **The email server is not ready yet. Try again in a few minutes.** | The server is being set up or is changing its plan: wait, the dialog updates by itself |
| **This server is full. Pick another one, or add inboxes.** | Pick a server with room, or detach a mailbox you no longer need. For a larger package, **Add inboxes** opens **Change plan** where a larger size can be taken, and otherwise says to write to support |
| **This server is paused. Open billing to see why.** | Click **Open billing** (the plan is on hold or has ended) or **Buy email** (its package left the plan) beside the server |
| **Setting this server up failed. Pick another server, or write to support.** | Pick another server, or write to support@getsales.io |
| **This server is no longer in the workspace. Pick another one.** | The server left the workspace after the dialog read it: pick another one |
| **Every inbox your plan holds is in use. Add inboxes, or detach a mailbox you no longer need.** | Detach a mailbox you no longer need, or take a larger package: **Add inboxes**, or write to support@getsales.io where the dialog says so |
| Google says the app is blocked or not allowed | The Workspace admin has not trusted the app, or gave a level other than **Trusted**: [the Google setup](#what-must-a-google-workspace-admin-do-before-a-mailbox-connects) |
| Microsoft refuses the sign-in or asks for an admin's approval | The organisation lets only admins approve outside apps: a Microsoft 365 admin approves it, then click **Start again** and sign in |
| The consent tab was closed before it finished | Click **Open the sign-in page** in the dialog, or **Start again** for a new sign-in |
| The dialog reads **Still waiting for the sign-in**, or the tab ends on **Mailbox not connected** with "This connection request took too long." | The provider's consent lasts 15 minutes, so one finished later lands nothing: click **Start again** and sign in again |
| "maya@acme.example is already on Daniel Okafor. Nothing was moved." | The account you signed in with is a mailbox another sender profile holds: click **Move it here** and confirm, or **Sign in with another account** |
| "This sign-in link expired before anyone signed in. Get a new one." or "This sign-in link was already used. Get a new one." | Click **Start again** |
| "This sender profile has too many sign-in links open. Finish one of them, or try again tomorrow." | Finish a sign-in that is waiting, or come back the next day |
| "The sign-in's progress cannot be read right now. A finished sign-in still puts the mailbox on this profile." | Click **Try again**: a sign-in that finished has landed the mailbox anyway |
| **Mailbox added, on hold: the email server has no free inbox.** | The mailbox landed and waits for an inbox: detach a mailbox you no longer need, or take a larger package |
| **Mailbox added, but its sign-in did not hold. Sign it in again from its card.** | Click **Reconnect** on the mailbox's card |

A mailbox that was connected and stops working: [Why a mailbox says Reconnect needed](/kb/sender-profiles/troubleshooting#why-does-a-mailbox-say-reconnect-needed-or-disconnected).

## Which refusals does a mailbox connect answer over the API?

A mailbox connect, over the API ([`connect_sender_profile_imap_mailbox`](/api-reference/unibox/sender_profiles/connect-an-imap-mailbox-to-a-sender-profile)) or from **Sign in with Google** or **Sign in with Microsoft** in the app, checks the plan's inboxes first, then the email server, and a refusal creates nothing: no mailbox and no sign-in link. With no `email_server_sid`, the connect takes the oldest active server with an inbox free. When none can take the mailbox, the refusal is the closest server's: one being set up or changing its plan first, then a full one, a suspended one, a failed one.

| Refusal | Sentence | When |
|---|---|---|
| `402` `email_inboxes_full` (`error.context.reason`, with `limit` and `used`) | "All 100 inboxes of this workspace's plan are in use. Detach a mailbox you no longer need, or add inboxes in Settings, Billing." (the plan's number). With none: "This workspace's plan has no inboxes. Pick a plan in Settings, Billing." | Every inbox of the plan holds a mailbox, or the plan has none, as on the trial |
| `409` `email_server_missing` (`error.context.reason`) | "This workspace has no email server. Add an email package in Settings, Billing." | The workspace has no email server |
| `422` `email_server_unknown` (`error.field_errors.email_server_sid[0].rule`) | "This workspace has no email server with this sid. Pick one that mailboxes/servers lists." | `email_server_sid` names a server the workspace does not hold |
| `409` `email_server_not_ready` (`error.context.reason`, with `status`, `step` and `steps`) | "This email server is still being set up (step 4 of 10). Try again in a few minutes.", or "is changing its plan". With its state unknown: "This email server is not ready for a new mailbox yet. Try again in a few minutes." | The server is being set up or resized: retry the same call in a few minutes |
| `409` `email_server_suspended` (`error.context.reason`, with `suspended_reason`: `payment_failed` or `unpaid`) | "This email server is suspended until its billing is settled in Settings, Billing." | Billing holds the server |
| `409` `email_server_failed` (`error.context.reason`) | "This email server could not be set up. Pick another server, or contact support." | The server's setup failed |
| `402` `email_server_full` (`error.context.reason`, with `inbox_capacity` and `inboxes_used`) | "All 100 inboxes of this email server are in use. Detach a mailbox you no longer need, or move to a bigger email package in Settings, Billing." (the server's number) | Every inbox of the server holds a mailbox |

## What does a mailbox connect not do?

- **No Google or Microsoft connect in the API reference or the MCP tools:** their sign-in starts only from **Add mailbox** in the app.
- **No email on the trial or the Free plan:** no mailbox connects on either until the workspace has a paid plan with an email package.
- **No move between servers:** a connected mailbox stays on the email server it landed on, and GetSales has no step that moves it to another one.
- **No warm-up emails:** a mailbox's **Warmup** is a sending ramp on its own daily sends. It exchanges no emails with other inboxes.
- **No tracking without a tracking domain:** opens, clicks and the unsubscribe link of a mailbox need a verified tracking domain set on it: [Set up a tracking domain](/kb/sender-profiles/tracking-domains). Without one, a workflow whose **Send email** step asks for any of them is not published (`tracking_domain_required`), and a due email that holds the unsubscribe link waits until a domain is verified.
- **No signature of its own:** the signature is the sender profile's, and the mailbox appends nothing to an email.
- **No cap per sender profile:** only the plan's inboxes, and the free inboxes of the workspace's email servers, limit how many mailboxes connect.

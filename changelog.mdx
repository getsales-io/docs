<Update label="2026-11-08" description="A Stop that holds, a daily limit that waits, and searches that say what they could not match">
  **A Stop on a column or a table stops the column.** `POST /api/playtable-runs/cancel` with
  `field_sid` or `playtable_sid` also turns `config.auto_run` off on the action columns it stops and
  sends back the cells queued in their auto-run queue, so new rows do not start them again a minute
  later. The answer adds `backlog_cells_count` (those cells, also counted in `reverted_cells_count`)
  and `auto_run_off_field_sids`; a `dry_run` names the columns it would turn off. A cancel by
  `run_sid` stops that run alone, as before. To run a column by itself again, update its `config`
  with `auto_run: true`, sending the whole `config` back.

  **A daily credit limit waits instead of failing.** A cell of an `auto_run` column that meets the
  column's `daily_credit_limit` before it spends anything stays `queued` with `error_msg`
  `daily_credit_limit_reached` and runs after 00:00 UTC, when the day's spend starts over. On a
  column without `auto_run` it still ends `error` with the same reason.

  **An AI search that could not match a word stops and says which.** When a word of an `ai_search`
  description matches no search value, the source pauses after planning with `status_reason`
  `filter_unresolved`, and `payload.plan_warnings` names the words. Resuming it searches without
  them; other words mean a new source.

  **Web search is priced as research.** `POST /api/playtable-fields/estimate-credits` prices an Ask AI
  column with `web_search` on the results each search reads back as input, and such a call may take up
  to 240 seconds. The column's `tool_sid` for `action_gtm_tool` lists every read it takes, the
  latest posts and the full profile among them.
</Update>

<Update label="2026-11-08" description="The reference keeps what an integration builds on">
  **What only the app calls left the reference.** The REST reference lists 322 operations, where it
  listed 411. The ones that left keep serving the GetSales app and are not part of the public contract:
  in ID and Teams the checkout and billing changes, sessions, OAuth clients and grants, white label
  administration, notifications, a team's deletion and its transfer. In Unibox the connect flows of
  LinkedIn accounts and mailboxes, the AI SDR's training and drafting helpers, and what acts on a
  channel from a message (a reaction, a delete on LinkedIn). In Playtables the metrics, suggest and
  estimate helpers, a column's and a table's cancel routes, and act and draft on an activity. In
  Signals a site's key pages and tracked events, which the site's own record carries now, and the
  signal preferences. In Integrations a single delivery's retry (the replay below takes a window) and
  the OAuth completion step.

  **New in the reference.** `POST /api/workflows/{sid}/add-people` adds people to a workflow in one
  call, and a person the workflow already holds stays as they are. `POST /api/people/{sid}/move` moves
  a person to another table. `POST /api/playtables/{sid}/archive`, `unarchive` and `duplicate`.
  `POST /api/playtable-fields/estimate-credits` prices a run before it starts, and
  `POST /api/playtable-runs/cancel` stops runs. The sender profile variables (four operations),
  `POST /api/agents/fix`, `POST /api/provider-connections/{sid}/crm-metadata` and
  `POST /api/webhooks/{sid}/replay`.
</Update>

<Update label="2026-11-08" description="Bulk edits on a table, and the Stop's numbers">
  **Six bulk edits run.** A `bulk` run of `create_playtable_run` carries out every operation it
  lists: `add_tags`, `remove_tags` and `replace_tags` (`params.tag_sids`), `set_field_value`
  (`params.playtable_field_sid` and `params.value`, null clears), `add_to_workflow`
  (`params.workflow_sid`, `params.restart`) and `cancel_from_workflows` (`params.workflow_sids`,
  or every workflow), beside `delete_objects` and `move_to_playtable`. They answered
  `501 not_implemented` before. Each operation checks its parameters when the run is created and
  answers `422` with the field named, so a run that cannot do its work never starts.

  **The Stop shows its numbers first.** Over MCP the first call of `cancel_playtable_runs` stops
  nothing: it runs the dry run itself and carries the counts in `preview_result` beside the
  `commit_token`. A REST caller still sends `dry_run: true` to read them.

  **A tool the public address leaves out says so.** On `https://mcp2.getsales.io/mcp/public`,
  `describe_tool` and `call_tool` with the name of a tool that acts on a channel answer that it is
  not on this address and is done in the GetSales app.
</Update>

<Update label="2026-11-08" description="Twenty tool groups and the public MCP address">
  **One group per entity.** The MCP server's tools are regrouped into twenty groups named by what
  they belong to: `playtables.tables`, `playtables.columns`, `playtables.rows`, `playtables.crm`,
  `playtables.sources`, `playtables.workflows`, `playtables.workflow-records`, `inbox`,
  `sender-profiles`, `sender-accounts`, `ai-sdr.agents`, `ai-sdr.training`, `signals`,
  `workspace.team`, `workspace.access`, `workspace.billing`, `workspace.website-tracking`,
  `workspace.integrations`, `workspace.webhooks` and `workspace.whitelabel`. A group's URL repeats
  its id (`https://mcp2.getsales.io/mcp/inbox`, `https://mcp2.getsales.io/mcp/ai-sdr/training`),
  `search_tools` takes the id as `toolset`, and `list_toolsets` answers the map. The
  [MCP overview](/mcp/overview) lists the groups with what each is for.

  **The public address.** `https://mcp2.getsales.io/mcp/public` is the URL to connect: four
  meta-tools over the groups, without the tools that send, set up a sender profile's accounts or
  read LinkedIn itself. [Connect a client](/mcp/connect) uses it in every example. The groups' own
  URLs and the full facade at `https://mcp2.getsales.io/mcp` serve the tools of each group.
</Update>

<Update label="2026-11-08" description="A file a message carried can be fetched on demand">
  **Bring an old file in.** A file GetSales does not hold (a message from before the sender
  profile connected, a message of your own team sent from the channel's app, or a fetch that gave
  up) can be asked for: `POST /api/messages/{sid}/fetch-attachment` with the file's `index` puts it
  back on its way, one call per file, one browser action of the sender profile's budget on
  LinkedIn. The row comes back with the file `pending`. It lands minutes later and
  `messages.attachments-changed` says so. A voice message is transcribed once it lands. A stored
  file, a GIF, a file past the cap or one the channel refuses answer `attachment_not_fetchable`.
</Update>

<Update label="2026-11-08" description="Sender variables: one text for a pool of senders">
  **Write a text once.** A workflow step's text and a play's message read the sender profile they
  go out as: `{{sender.first_name}}`, `{{sender.last_name}}`, `{{sender.full_name}}`,
  `{{sender.label}}` and every variable your team keeps, `{{sender.<slug>}}`.

  **Team variables.** `POST /api/sender-profile-variables` adds a name for the workspace, and
  `PATCH /api/sender-profiles/{sid}` takes each sender profile's `variables`, merged by slug.
  `POST /api/sender-profiles/variable-usage` says which workflows and plays use one.
</Update>

<Update label="2026-11-08" description="Webhooks filter on the payload and replay an outage">
  **Filter on the payload.** `filters.where` delivers only the events that pass a condition on
  the payload, and `["*"]` subscribes to every event of the catalog, later ones included.
  The [webhooks guide](/guides/receive-webhooks) has the grammar and the limits.

  **Replay.** `POST /api/webhooks/{sid}/replay` puts the failed and platform-cancelled deliveries
  of a window back on the wire.

  **Reads.** `delivery_stats` gives a webhook's 24-hour count and last outcome, `include webhook`
  attaches a delivery's subscription, the search sorts by the failure columns and filters on
  `filters.account_sid`, and every delivery carries `occurred_at`. A test send can dry-run a filter
  on a `sample_envelope`, and a mailbox's history import no longer fires `conversations.created`
  for its old threads.
</Update>

<Update label="2026-11-01" description="The developer documentation opens">
  **The public contract, documented from its source.** The [API reference](/api-reference/overview)
  covers the five services of the platform, 411 operations in all: Playtables (142), Unibox (125),
  ID and Teams (88), Signals (30) and Integrations (26). Every page is generated from the same
  Zod registry that defines the MCP tools, one endpoint per tool, so the playground shows what the
  server validates. The guides cover [authentication](/authentication), the
  [response envelope and the 16 error codes](/concepts/envelopes-and-errors),
  [paging and filters](/concepts/pagination-and-filtering) and
  [webhooks](/guides/receive-webhooks).

  **The MCP server.** `https://mcp2.getsales.io/mcp` exposes the same tools to Claude, Cursor,
  ChatGPT, Claude Code and any other MCP client, through OAuth or a `gs_live_` API key.
  [Connect a client](/mcp/connect) has the setup for each.
</Update>

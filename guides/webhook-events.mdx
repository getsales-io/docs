Every delivery is the same envelope, with the event's own fields under `payload`. This page lists those fields for each of the 33 event types. How a delivery is signed, retried, logged and replayed is in [Receive webhooks](/guides/receive-webhooks), and the same bodies, as schemas, are in the Callbacks block of [create-webhook](/api-reference/integrations/webhooks/create-webhook).

A field is on every delivery of its event unless its type says optional, and a field with no value arrives as `null`. A nested field is written with its path, as in `created_by.actor_type`.

## The envelope

| Field | Type | Description |
| --- | --- | --- |
| `webhook_log_sid` | string | This delivery: the same on every retry of it, the receiver's dedup key (also X-Webhook-Log-Id) (wh_lg_...). |
| `type` | string | The event type, one of the 33 below (also the X-Webhook-Event header). |
| `emitted_at` | string | When the event was emitted: ISO 8601 in UTC to the second, e.g. 2026-11-03T10:15:30+00:00. |
| `occurred_at` | string, optional | Equal to emitted_at today, the object's own moment once a producer names one; absent on a delivery stored before 2026-11-03: ISO 8601 in UTC to the second, e.g. 2026-11-03T10:15:30+00:00. |
| `team_sid` | string | The workspace (ts_tm_...). |
| `trace_id` | string | The trace of the request that caused the event (also X-Trace-Id). |
| `payload` | object | The event's own fields, listed below for each type. |
